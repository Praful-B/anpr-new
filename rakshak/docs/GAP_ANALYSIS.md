## Cross-cutting gaps (affect all files)

| Gap | Severity | Detail |
|-----|----------|--------|
| **Error response shape** | CRITICAL | Zero endpoints produce `{"error": {"code": "...", "message": "...", "field": null}}`. Every error uses FastAPI's default `{"detail": "..."}`. No custom exception handler registered in `main.py`. |
| **Thin handler violations** | CRITICAL | 14 occurrences of `db.add()` / `db.commit()` inside `api/` files (auth, complaints, devices, hotlist, admin, sightings). Business logic in api/ instead of services/. |
| **No TimestampMixin** | HIGH | All 6 models with timestamps define `created_at`/`updated_at` with identical lambda defaults. No shared mixin exists. |
| **No InvalidStateTransition exception** | HIGH | `verification.py` raises plain `ValueError`. Custom exception class does not exist anywhere. |
| **Plate privacy in logs** | HIGH | `scheduler.py` logs `plate=entry.plate` on line 68, risking plate values in production logs. |

## Numbered completion plan (dependency order — maps to Phase 6 of spec)

1. **Phase 1 — Backend foundation:** Fix `config.py` (add missing settings, MASTER_KEY validation), fix `main.py` (CORS, exception handler, health endpoint), create `TimestampMixin`, fix all schemas (`from_attributes`, `extra="forbid"`), fix `security.py` (refresh token claims, decode_token type check), create `InvalidStateTransition` exception.
2. **Phase 1 continued:** Fix error response shape globally (custom exception handler + all HTTPException usages). Move business logic from api/ to services/ thin handlers. Create `services/rate_limit.py`, `services/matching.py`, rename `normalizer.py` → `plate_normalizer.py`.
3. **Phase 2:** Fix `services/verification.py` (audit log + broadcast inside service), fix `services/scheduler.py` (add sighting/audit purge, broadcast on expiry, audit log on expiry). Fix `services/dedup.py` (add lat/lng params). Create `services/crypto.py:unwrap_key()`.
4. **Phase 2 continued:** Fix all test gaps (conftest isolation, freezegun, missing test cases, exhaustive illegal transitions).
5. **Phase 3:** Fix device registration/revocation. Fix `ws_manager.py` extraction.
6. **Phase 4:** Fix sightings endpoint (202 status, pagination). Fix analytics (move to services, add response models). Fix detect endpoint log message.
7. **Phase 5:** Fix mobile match.ts exports, queue.ts flush, crypto.ts secure-store.
8. **Phase 6:** Fix dashboard ws.ts missed-event replay. Fix alembic (indexes, partial index, PostGIS ordering).
9. **Phase 7-10:** Integration testing, simulator verification, manual E2E, documentation.
